EeveeSpotify Version Update Locations
=====================================

The authoritative setter is **Scripts/bump-version.py**, run by the
`.github/workflows/bump-version.yml` workflow (Actions → "Bump version").
It updates every version this repository displays, in one pass:

1. control
   - `Version: X.Y.Z`   <- the .deb package version (also the IPA filename)

2. Sources/EeveeSpotify/Tweak.x.swift
   - `static let version = "X.Y.Z"` (the tweak's runtime version)
   - `static let buildNumber = "N"` (shown next to it in the settings page / log)

3. README.md
   - the "Public release" row of the Versions table: `vX.Y.Z`
   - the "Development last updated: `YYYY/MM/DD`(build N)" line

Run it locally with:

    python3 Scripts/bump-version.py --version 6.6.9
    python3 Scripts/bump-version.py --version 6.6.9 --build 110
    python3 Scripts/bump-version.py --version 6.6.9 --no-readme --dry-run

`--build` defaults to the current Tweak.x.swift buildNumber + 1; `--date`
defaults to today in Asia/Shanghai; `--no-readme` leaves README.md alone;
`--dry-run` prints what would change without writing.

Why a workflow as well as the script: it validates the input, shows the diff
even when you do not want to commit, and commits with the repository identity
(zbzxbg <yuanhainigu@outlook.com>) using an English message. It is manual on
purpose — bumping a version is a release action, and a push-triggered commit
would retrigger itself.

Derived, never typed
--------------------
- `build-ipa-local.sh` and both build-ipa workflows read the version from
  control at run time (`grep -E '^Version:' control`), so an IPA cannot be
  built with a stale package version.
- The `.deb` filename and the IPA output name are derived from control.

If you add another place that shows the version, add it to
`Scripts/bump-version.py` (and this list) — do not reintroduce a "remember to
edit this by hand" step.
